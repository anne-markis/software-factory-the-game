# Decision Audit: Issue #10 (Page is unreadable in dark mode)

## Agent A: Model Chooser
**Timestamp:** 2026-08-02 08:30 PDT
**Decision:** sonnet
**Rationale:** index.html's style block (102 lines total) is self-contained and confirms the issue's diagnosis exactly: body sets no `color-scheme` and no explicit `color`/`background`, so under forced/`prefers-color-scheme: dark` only the UA canvas inverts while the ~7 hardcoded hex tones (`#666` dim labels/arrows, `#999` panel/node borders, `#a60` gamble tag + cannot-afford reason accent, `#c00` cannot-afford override, `#444` node description text, `#fdd` stall banner background, plus the implicit default-black body text) stay put and lose contrast. A bare `color-scheme: light dark` alone is not sufficient — it only auto-inverts UA form controls and the default canvas/text pairing, not these authored hex values — so real work is picking accessible dark counterparts for each of those ~7 tones and wiring them in, most cleanly via CSS custom properties overridden in a `@media (prefers-color-scheme: dark)` block. The SVG diagrams in loopDiagram.ts and inProgressPanel.ts use `stroke="currentColor"`/`fill="currentColor"` with no inline `color` override in either file, so they inherit correctly from whatever text color is set upstream and need no separate fix once body/container color is corrected. This is a single-file, low-ambiguity, well-scoped CSS fix with a clearly stated fix direction in the issue, but it requires judgment to choose contrast-safe dark-mode color pairs and decide the override structure (custom properties vs. flat block) rather than being a pure mechanical find-and-replace, which puts it above haiku; it does not touch app logic, state, or multiple files, which puts it below opus.
**Handoff to Agent B:** Use CSS custom properties (e.g. `--fg`, `--fg-dim`, `--border`, `--accent-amber`, `--accent-red`, `--desc`, `--stall-bg`) defined on `:root` for light values and overridden inside `@media (prefers-color-scheme: dark)`, plus `color-scheme: light dark` on `:root` or `body`, so all ~7 hardcoded hex colors (#666, #999, #a60, #c00, #444, #fdd, and the default body text/background) get consistent dark variants and the currentColor-based SVGs in loopDiagram.ts/inProgressPanel.ts inherit correctly without needing their own edits — verify visually with resize_window colorScheme: "dark" as the original issue reporter did.
